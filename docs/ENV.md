# Environment and secrets

Never commit secret values. Frontend variables are public by design; everything else lives in the backend's secret store and is read only by edge functions.

## Frontend (Vite, `.env`)

Generated by Lovable Cloud. Do not edit by hand.

| Variable | Public | Used by |
|---|---|---|
| `VITE_SUPABASE_URL` | yes | Generated client; direct `fetch` calls to demo functions (`demoAi.ts`, `demoEmailConfirmation.ts`, `DemoNotificationDelivery.tsx`) |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | yes (anon key) | Same |
| `VITE_SUPABASE_PROJECT_ID` | yes | Generated config |

Other public configuration kept in code:

| Value | Location |
|---|---|
| Cloudflare Turnstile site key | `src/lib/turnstile.ts` (`TURNSTILE_SITE_KEY`). Its allowed hostnames must include every domain that serves the forms |
| WhatsApp number and prefilled message | `src/lib/whatsapp.ts` |
| Prices and implementation fees | `src/lib/pricing.ts` |

## Edge function secrets

| Secret | Set by | Used by | Notes |
|---|---|---|---|
| `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` | Platform, automatic | All functions | The service role key is not retrievable on Lovable Cloud |
| `LOVABLE_API_KEY` | Platform, managed | AI Gateway calls (`generate-str-narrative`, `refine-str-narrative`, `demo-str-narrative`, `screen-adverse-media`, `generate-roadmap`), Lovable Emails (`sendTemplateEmail`), `handle-email-events`, `preview-transactional-email` | Rotate through Lovable, not the secret store |
| `LOVABLE_SEND_URL` | Platform, optional | `send-email.ts` | Overrides the email API endpoint when present |
| `TURNSTILE_SECRET_KEY` | Owner | `public-submit` | Pairs with the site key above |
| `IP_HASH_SECRET` | Generated | `public-submit` | Keys the hashed IPs stored in `rate_limits` |
| `EMAIL_TRACKING_SECRET` | Generated | `email-track`, `_shared/email-tracking.ts` | Changing it invalidates every existing tracking link |
| `WEBHOOK_SECRETS_KEY` | Generated | `ingest-transaction` | AES-256-GCM key for `institution_webhook_secrets`. Losing it makes every issued webhook key unusable |
| `CRON_SECRET` | Generated | `generate-ctr-batch`, `refresh-sanctions-database`, `rescreen-adverse-media` | Must match the vault entry `cron_secret` |
| `RESEND_API_KEY` | Connector | Not used by current code | Left over from the earlier email setup. Managed under Connectors |

## Database vault entries

Read by SQL (cron jobs and `request_risk_recalculation`), not by functions.

| Name | Used by |
|---|---|
| `cron_secret` | `x-cron-secret` header for both cron jobs; must equal `CRON_SECRET` |
| `email_queue_service_role_key` | Bearer token for cron calls and for `request_risk_recalculation` -> `recalculate-risk-score`. The name is historical (from the retired email queue) |

## Tooling and tests

| Variable | Used by |
|---|---|
| `LOVABLE_DB_MIGRATION_URL` | `drizzle.config.ts` (drizzle-kit migrations) |
| `RUN_ACCESS_INTEGRATION` | Enables `src/lib/*.integration.test.ts`, which are skipped by default because they hit the live database |

## Hosting facts

- Database, storage and functions: Lovable Cloud on AWS eu-west-1 (Ireland). No Nigerian region.
- Domains: `apexaml.com`, `www.apexaml.com`, plus the `apexaml.lovable.app` published URL. Preview and published apps share one backend.
- Email sender: `notify.apexaml.com` (delegated to Lovable), shown as `apexaml.com`.
