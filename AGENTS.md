# Project rules

- Live destructive authorization tests use temporary Auth API accounts and rollback-only database fixtures with real database roles and JWT claims; never weaken audit triggers or tenant policies for cleanup.

- Platform role changes use a caller-authenticated atomic RPC for mutation, audit and per-recipient in-app notices, with serialized lockout checks and database-backed call limits; a dedicated non-tenant audit scope prevents platform events from granting tenant memberships.

- Audit logs use serialized per-institution SHA-256 chains, server-side role-scoped verification, and unconditional mutation triggers; inserts never request a returned row because writers may lack read access.

- Keep platform authorization separate from tenant membership; tenant RLS uses institution roles and read-only expiring support grants, never platform role bypasses, so staff privileges cannot expose customer data.
- Activate and revoke support access only through authenticated security-definer RPCs that atomically write audit events; require MFA and a scoped justification to prevent silent support grants.
- Guard service-credential tenant functions with exact system credentials or verified customer membership and operation roles; read-only support cannot invoke tenant writes or AI drafting.

- Scope public-page dark variables to MarketingZone, and propagate its scope to portal content via React context; app theme preferences must remain independent.
- Use semantic muted-on-dark text utilities for low-opacity marketing copy; retain translucent surfaces and higher-opacity text separately.
- Keep dark primary foreground accents separate from filled primary button tokens, with shared scoped utility compatibility for existing and preserved UI; this prevents translucent foregrounds or button hover utilities from lowering contrast.
- Keep field borders and muted text in theme tokens, with scoped marketing overrides for legacy translucent field boundaries, placeholders and focus rings; this preserves glass surfaces and app-theme independence.
- Keep green-control foregrounds and roadmap-specific sidebar/warning roles in semantic tokens; scope roadmap sidebar overrides to its page so other app sidebars retain their own styling.

- Keep subscription amounts and implementation fees in `src/lib/pricing.ts`, and derive calculators and price displays from them so pricing changes stay consistent across the site.
- STR workload illustrations share one reactive assumptions store and pure calculation in `src/lib/strEstimate.ts`; both calculators and InnovationStory consume it so edits and figures cannot diverge.
- Register requested email templates in the shared transactional registry and invoke the managed sendTemplateEmail helper from validated server paths; this keeps delivery, suppression and unsubscribe handling consistent without recreating the retired queue.
- Use the shared LegalFooter in email templates; this keeps company and data-protection notices consistent.
- Explicitly pass the server credential when invoking the queued sender and compare it against the configured credential; this supports current server keys without trusting decoded JWT role claims.- Every tenant table carries a NOT NULL institution_id with member-only RLS (private.is_institution_member), and tenant storage paths start with the institution_id; writers set it explicitly, with a fill trigger as a safety net, so rows and files can never be unscoped.
- Core banking webhooks authenticate with per-institution encrypted keys, signed timestamps and event_id idempotency recorded atomically with the queued transaction; the key alone decides the institution so payloads cannot cross tenants.
- Every public form and public tracker posts through the single public-submit function (src/lib/publicSubmit.ts): per-form table/column allowlist, server-fixed source, 10 KB cap, "website" honeypot, hashed-IP limits via consume_rate_limit, Turnstile for forms only, service-role insert and fixed-recipient alerts; the browser never picks tables, sources or recipients. Public tables have no anon INSERT policies; the superseded per-form functions stay until removal is approved.
- Shared reference tables (sanctions, regulatory) are readable only by institution members (private.has_any_institution) or platform admins; anonymous visitors read only narrow security-definer RPCs (get_taken_demo_slots, get_roadmap_lead_count), never the tables.
- Routes are split into marketing, internal, /demo/* (sample data) and protected /app/* (live) zones in src/lib/zones.ts; operational links go through useZoneNavigate/useZoneHref so navigation never leaves the current zone, and old top-level URLs redirect to /demo.
- Operational data goes through src/data-layer: hooks pick the demo provider (in-memory + localStorage) for /demo and marketing zones and the lazily loaded live provider for /app and internal zones; pages and components never import the backend client directly (enforced by demoIsolation.test.ts), so sample visitors can never read or write institution data.
- Live CSV case import parses client-side (src/lib/alertsCsv.ts) but saves only through the import_alerts_csv RPC, which re-validates, scopes to the caller's institution and writes its audit entry in one transaction, so partial imports or unaudited imports cannot happen.
- Every /app/* route sits behind ProtectedRoute plus InstitutionGate, which requires a user_institutions membership (platform roles never count); non-members get the pilot request form, which submits through submit-pilot-request using the session's verified email. Seed-backed UI (sample analysts, notifications) renders only in /demo, so /app shows only institution data.
- Demo entry at /demo submits the public-submit demo_entry form, which writes leads + demo_sessions, issues the confirmation code and sends the fixed internal alert; its returned id becomes the local demo store session.

- Demo event notifications are triggered from successful demo audit appends and delivered only through a scoped session-token bridge; the server selects fixed fictional templates and the session recipient, with atomic per-session/address reservations. This prevents arbitrary email and tenant-data access.
- Demo notifications are emailed only after the session's address is confirmed with a session-bound hashed code (confirm-demo-email); reserve_demo_confirmation atomically enforces send limits and validity, and reserve_demo_notification refuses unconfirmed sessions, so the browser flag is never the authority and unconfirmed sessions stay inbox-only.
- STR/CTR XML exports take reporting-entity details from resolveExportEntity: live reads the versioned institution profile (saved only via the admin-gated save_institution_profile RPC) and blocks on missing required fields; demo uses fixed DEMO values. This keeps placeholders out of live files and ties each export audit entry to a profile version. Live exports (including filed-CTR re-downloads) write their audit entry before the file downloads and abort if it fails, so no live file leaves unaudited.
- Demo STR drafting sends demo-str-narrative only the case id (plus draft/instruction when refining) and session token; the function loads cases from _shared/demo-seed-cases.data.ts (generated from the browser seed, checked by demoAiCases.test.ts) and refuses other ids. Prompts and demo guardrails live in _shared/str-prompts.ts; the service-only reserve RPC enforces kill switch, daily/session/IP caps and alert threshold from demo_ai_settings; off-format output or failure falls back to labelled pre-written text.
- Public rate limits key on _shared/client-ip.ts (Cloudflare-set cf-connecting-ip, which visitors cannot supply), never on x-forwarded-for.
- email_events is written only by service-role edge functions; email-track accepts only links HMAC-signed via _shared/email-tracking.ts and fails closed, so opens and clicks cannot be forged.
- Live STR AI functions require institution_settings.ai_drafting_enabled (set only via audited admin RPC), pseudonymise PII in-request via _shared/pseudonymise.ts, and alone insert 'ai' drafts with provenance; browsers save only 'analyst_edit' (trigger stamps author, freezes provenance).
- docs/ is the handover reference; update the matching file when zones, tables, RLS, functions, schedules or secrets change, so it never goes stale.
